# 本地 GPU 训练与 CPU 导出首次运行

训练工具已在视觉仓库 `tools/armor_pose_training` 建立，仿真继续负责数据生产。完成 GPU 训练、断点恢复、独立测试集评分、ONNX 导出和 CPU 数值一致性检查；这是可运行的训练基线，当前位姿精度不足以替代在线 PnP。运行命令、数据边界及部署接口由[工具说明](../../tools/armor_pose_training/README.md)维护。

## 验证方法与结果

假设一：本机 CUDA 环境能实际执行模型训练。用真实 GPU 前向/反向检查，再在既有首批数据上训练 5 轮，从最后断点恢复至总计 20 轮；检查梯度/损失有效、权重落盘、历史连续和验证损失变化。预期是优化实际发生，能够恢复，而不是仅打印 GPU 名称。结果通过；4 项监督/数据隔离检查通过，重复恢复已完成轮数被拒绝且权重及历史哈希未变，详见 [checks.json](checks.json)。

本机 Python 3.13.14、PyTorch 2.11.0+cu128、TorchVision 0.26.0+cu128，RTX 5060 Laptop GPU，CUDA 12.8 运行库支持 sm_120。[初始环境](environment.json)、[续训环境](resume_epoch_6.json)与[完整包版本](environment-packages.txt)保留；安装在视觉仓库独立虚拟环境，没有改全局 Python 包。

| 项目 | 实测结果 |
|---|---|
| 输入数据 | 8,866 张训练裁图、1,098 张验证裁图；测试集 1,122 张只在训练结束后评分 |
| 模型 | MobileNetV3-Small 特征层与多任务头，1,004,338 参数，随机初始化 |
| 训练 | AdamW、batch 128、AMP；20 轮，验证损失选择第 18 轮权重 |
| 损失 | 训练从 3.7847 降到 0.1998；验证从 3.8696 降到最佳 0.7068 |
| 时间 | 各轮训练+验证累计 259.39 s；不含安装、进程初始化及 checkpoint 写盘。首轮 69.69 s，续训首轮 15.59 s，其余轮中位数 9.64 s |
| 显存 | PyTorch 已分配显存峰值 410.58 MiB；不代表进程或显卡的全部显存占用 |

逐轮记录见 [history.jsonl](history.jsonl)。AMP 共跳过 3 个发生梯度溢出的更新，随后继续；没有把被跳过的更新称为成功更新。前几轮训练损失下降但验证滞后：第 5 轮同一 128 张验证裁图，eval FP32 / eval AMP 损失为 3.86905 / 3.86923，train 模式 AMP 为 1.20902。结合骨干 BatchNorm 的 momentum=0.01，此结果支持运行统计尚未跟上训练分布的解释；没有用验证集重新估计归一化统计或回传更新。后续验证损失下降，仍不能将全部剩余误差归因于此。

假设二：保存的权重能导出为等价 CPU 网络。对第 18 轮权重导出 ONNX，运行 ONNX checker，再用 32 张实际验证裁图按 batch 1/2/4 比较 PyTorch CPU 与 ONNX Runtime CPU 的全部输出，容差 atol=rtol=1e-4。结果通过；最大 logit 差 3.59e-5，最大位置输出差 7.63e-6 m，见 [导出元数据](export_metadata.json)。这些是数值实现差异，不是真值测量误差。

CPU 为 AMD Ryzen 9 8945HX，ORT 1.31.1，4 个计算线程，每组预热 10 次、计时 100 次：

| 同批候选数 | CPU 前向中位数 | P95 |
|---|---:|---:|
| 1 | 0.625 ms | 0.684 ms |
| 2 | 0.615 ms | 0.652 ms |
| 4 | 1.750 ms | 1.844 ms |

仅计已准备好裁图后的网络前向；没有候选提取、原图裁剪/缩放、输入准备、旋转解码或 IO。没有进行 CPU/GPU 训练加速倍数对照，也没有验证现有 C++ OpenCV DNN 的模型兼容性。

## 独立测试集精度

测试集包含 886 张正样本与 236 张负样本。所有受监督正样本都参与位姿统计，不通过存在性分数筛掉难例；完整按距离/斜视分层的数据见 [test_metrics.json](test_metrics.json)。

| 指标 | 结果 |
|---|---:|
| 装甲存在性（阈值 0.5） | TP 883、FP 7、FN 3、TN 229；精确率 99.21%，召回率 99.66% |
| 贴纸准确率 | 86.23%（886 张受监督样本） |
| 阵营准确率 | 98.98%（884 张受监督样本） |
| 深度有符号均值 / 标准差 | +0.0226 m / 0.7584 m |
| 深度绝对误差中位数 / P95 | 0.4285 m / 1.5820 m |
| 三维平移 RMSE | 0.7723 m |
| 旋转误差均值 / P95 | 31.11° / 57.48° |

整体有符号均值很小，不能据此说深度准确：0～2 m 组均值为 +0.2824 m，4～8 m 组为 −0.4611 m，正负偏差存在抵消。这次没有同输入的 PnP 对照，因此不报告学习模型优于或劣于 PnP 的定量比值。裁图来自仿真训练清单，也不能把存在性指标解释为完整图像检出率。

## 文件与剩余工作

实际训练结果留在 `.cache/armor-pose-runs/bootstrap_20261030/`：`best.pt`、`last.pt` 各约 12.30 MB，包含恢复所需优化器状态；`armor_pose.onnx` 约 4.03 MB。完整路径、大小和哈希见 checks.json。源码、最小相关文档和本目录的小型统计证据入库；数据、虚拟环境和权重不入库。

依赖安装时 CUDA wheel 下载遇到超时后成功续传；本机默认 PyPI 镜像无法找到 ONNX，改用官方 PyPI 成功。固定版本导出器使用 `dynamo=False` 的 TorchScript 路径，有弃用提示但实际导出、一致性与 CPU 检查通过；后续升级框架时须重新验证导出路径。

偏离原任务：无。当前完成训练基础设施及一次基线训练，尚未完成位姿精度优化、同输入 PnP 对照、真实候选定位下的完整视觉评估、置信度/不确定性校准、未训练相机与板型泛化或在线模型替换。K/D 输入不自动保证对新标定的泛化；ROS 与实车仍为后续任务。
