## 已确认的问题与实际修改

算法当前唯一维护说明见 [rm_tracker 数据流与算法](../../src/rm_tracker/README.md#数据流与算法)，这里记录本轮修改理由和证据。

| 旧路径问题 | 本轮修复 | 影响与验证 |
|---|---|---|
| 观测雅可比缺少半径列，并在更新前清掉半径互协方差 | 新增 11 维 BodyEkf，同时估计共享中心、速度、两组半径与高差 | 有限差分校验全部雅可比；不等半径/高差恢复测试通过 |
| 换板交换半径、板高及相位，没有一致协方差变换 | 固定体坐标索引，换板只选择对应观测函数，不变换整车状态 | 四板反复切换，公共车心连续；镜像 yaw 与重复板测试通过 |
| 装甲更新后又冻结/覆写 SPIN 车心，另行伪观测与圆拟合 | 实际 update 只由一个 BodyEkf 维护车体；旧辅助函数退出执行路径 | 实际 Tracker 900 帧同输入比较通过；没有两个各自维护的车心 |
| ROS/native 将短间隔变成 10 ms，将长间隔截到 100 ms | 共享 FrameClock，正间隔保持真实值；异常戳拒绝；超过 0.5 s 重建 | 0.5 ms、200 ms、重复、倒序、断流测试通过；Q 的整步与分步传播相等 |
| 建轨/失锁仍按帧数，交付频率改变持续时间 | 按实际 dt 累加，旧阈值按名义 10 ms 转持续时间 | 真实间隔进状态机；新增行为有明确兼容语义 |
| 以圆柱正前点代替旋转到达时刻的真实板，选板与解算延迟不一致 | 同一车体预测四板，选板与瞄准共享时域，使用切换惩罚与飞行时间一致性检查 | 实际 Tracker 使用新路径并产生非零许可；没有把许可当成命中 |
| 近距离直接几何瞄准，表外回退仍标为有效；查表边界权重可外推 | 表内统一补偿，表外拒绝；查表坐标限界 | 表外无效测试通过，原生管线回归通过；未新增在线迭代器 |
| 发弹门控后又 EMA 改变发送角度 | ROS/native 发布门控评估过的原解 | 原生适配已编译/回归；ROS 源码更新但未编译运行 |
| 只输出九维板参考状态，难以区分车体与当前板 | 快照新增 11 维 body 状态、协方差对角、ready、实际间隔与重建标志；保留原九维渲染兼容字段 | 原生管线编译与回归；旧字段不冒充完整车体状态 |

旧 ExtendedKalmanFilter 九维类及圆拟合等辅助函数仍保留供对照，不能据源码中它们仍存在而认定当前算法仍执行冻结半径/车心。车型半径表仅是初始化先验；默认未知车型每次重置第二半径先验，避免继承上个目标残值。半径与关联上下界仍沿用 tracker 参数；jump_cooldown 不再用于车体关联。

## 假设、边界与评价方法

四板同组相差 180°并保留高度；组间相位 90°来自本地现有名义模型，没有本次实车标定。半径/高差测试值刻意不等，不由仿真精确参数喂给算法。中心 z 选 A 组板平面作为规范，不是物理底盘中心高度。

模型输入只有匿名板估计及其方向；测试层真值仅生成观测和评测。实际 ROS 继续视觉自有 IMU，MCU 只沿用已接入颜色/弹速；没有新增绝对位姿/速度、里程计、消费时间、完美动态外参或执行回执。相对速度不是敌方绝对速度。MCU 姿态不接入。图像处理后主机戳、IMU 发布戳仍不能证明采样同步；本轮不把消除 dt 截断写成解决全部时延。

测试 1：1200 帧共享车体，输入含 0.5/10/40 ms 间隔、四板交替、每轴 2 mm 位置噪声、3 m 野值、10 帧丢失。估计端不接收板索引、真值半径、真值速度。另做全部雅可比有限差分、协方差对称/半正定、同组半周对称/板高不变、镜像 yaw、重复观测、拒绝不改变状态测试，以及 3 m/s² 相对加速场景。期望共同中心连续、两组几何独立恢复、真实时间 Q/P 自洽；失败则保留输出、不改门槛。

测试 2：实际 Tracker 同一组 900 帧匿名可见板观测，旋转 3 rad/s、中心水平相对平移并有小幅正弦侧移、不等半径/板高。两版从同一份测试驱动生成相同输入；inputs.csv SHA256 完全相等：`a6e0cb0258af293154d863ebbcae95cd005af929a473bc32ea0b696b1fc1c5b9`。基线从 `6c3e6f8` 抽取未修改 tracker/ekf/tf 源文件，独立编译；新旧都采用理想云台跟随各自命令。比较中心时，位置观测已经在稳定方向系，故不同云台命令不改变这份输入。该实验绕过检测/PnP实际误差，不能代表图像链路公平评测或实车精度。

中心误差仅取 x/y 欧氏距离；实际 Tracker 汇总第 101–899 帧，BodyEkf 汇总第 101–1199 帧。新旧采用同一汇总区间；CSV 保留全部启动与失败帧，不用 P95 代替最大误差。放行数只是许可帧数，未模拟实际射速/弹丸/命中，不作命中率比较。旧基线 --reference 模式跳过新算法专用断言但完整输出原统计。

## 复现与环境

在视觉根目录运行 `powershell -File outputs/body_model_repair_20261029/reproduce.ps1`。可指定 OpenCVRoot、EigenRoot、OutputDirectory。脚本构建新核心与八项检查，输出 body/tracker；从 Git 固定基线抽取来源单独构建，输出 baseline，并检查两版 inputs.csv 摘要一致。原始逐帧 CSV、二进制、来源快照留本机；入库本文、摘要统计、复现脚本与 evidence.sha256。

本机 GCC 15.2、Eigen 3.4、OpenCV 4.12。前一阶段报告的默认 OpenCV 路径确实缺失，本轮定向找到 `.deps/environment-path-check/install/runtime-path-check/opencv` 的已有安装；没有重装依赖或修改共享配置。默认显示构建缺 GLFW 来源，因此新增 DT46_HEADLESS_TESTS 构建入口验证实际核心/管线/通信，未宣称 GUI 媒体或仿真联机跑通。初次旧身份测试因 Windows 子进程中文解码出错而失败，明确 UTF-8 后固定归档摘要通过；测试检查 Git 历史，没有把新源码哈希写成旧源码身份。编译中两处编辑错误已在实际编译反馈后修正。复现脚本首跑因变更输出目录造成基线源码路径与 CMake 缓存冲突，已固定源码快照路径，保留 first_reproduction_failed.log；最终 final_verification.log 确认脚本完整通过。evidence.sha256 记录本机文件原始字节摘要，文本跨平台换行转换后摘要可能不同。

## 尚未完成与风险

- 没有 ROS 编译、实车、真实图像闭环、真实云台/枪口动态、真实弹丸命中或执行反馈验证。原生历史 optical/动态枪口输入仍只能当真值辅助回归；新核心实际已接入，但该入口的实车输入公平问题未解决。
- CV/EKF 的 Q 能跟随本次加速场景，但不是加速度上界或严格命中保证。多板 PnP/IMU误差可能相关，当前顺序观测更新未建跨板相关噪声，协方差可能过于乐观。
- 目前相邻相位固定名义 90°、四板模型；不是任意车型、倾斜车辆、长时多目标、半径缓慢变形或高速混叠的通用保证。ROS 板消息仅 yaw，无法恢复丢掉的完整板法线。
- 时间补偿配置仍是显式假设，需要实际曝光/IMU采样延迟与抖动证据。姿态补偿不提供底盘平移速度；没有执行回执就不能宣称确认发弹执行时刻。
- 旧板速度/反小陀螺辅助及若干未调用的旧函数仍存在；当前体状态与目标预测已独立于旧的圆拟合/冻结路径，但后续可继续用实验替换这些遗留判据。未做整条链路最坏时延保证。

偏离：无超出本轮用户授权的实现范围。采用了新的共享体 EKF，而非只改旧 dt 截断；保留原始分支与失败证据。当前交付是底层修复与原生验证，不宣称完整自瞄目标已经验收。
